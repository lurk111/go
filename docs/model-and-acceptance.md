# 真实模型接入与首期收尾

范围：按用户授权复用 Akmatori 活跃模型配置，独立 Go 客户端调用 Responses 兼容中转站；补充具体处理建议、发现时延和实验规模持续运行验收。模拟业务和本地通知保持原有范围，没有新增生产接入或群机器人。

## 业务行为

- 规则确定异常类型及证据支持程度；模型在已有证据内补充中文分析和人工检查建议。页面明确标记“规则 + AI 分析”，AI 建议标记需要人工核对。
- 额度、限流、超时、提取失败、Worker 心跳异常、空结果、缺失结果及结构异常有各自检查建议；模型不可用时仍能使用这些建议。
- 模型没有 SSH 或业务写入权限，不自动重试任务、修改数据库或重启服务，不将人工关闭视为恢复。
- 一次调用、最多 60 秒，与诊断任务共用总截止时间；模型请求在数据库事务之外执行。人工关闭期间返回的报告仅归档，不追加通知。
- 当前中转站模型使用低推理强度、2400 输出 token 上限，以满足简短排障分析的时延预算；单次超时仍可能发生，不保证第三方模型可用性。
- 输入结构脱敏，输出引用必须对应已有且可用证据，短证据编号映射回原始编号后持久化。未知引用、额外授权字段、非 JSON、错误状态及超时均回退规则报告。引用合法不代表自然语言分析必然正确，仍需人工核对。
- 密钥本地私密文件与运行时只读挂载，不写入镜像、日志或 API 响应；不更改 Akmatori 的配置。模型错误只记录固定错误码及 HTTP 状态，不保存上游错误响应正文。

## 验收方式

- Go 测试包含模型鉴权、限流、上游故障、无效 JSON、伪造证据编号、越权字段、取消、重定向、输入脱敏、持久化校验与模型回退/人工关闭竞态。
- Go 集成测试使用专用 test-mysql，与主监测器的模拟业务 MySQL 分离，避免运行测试时产生额外告警及付费模型请求。运行脚本结束后停止测试数据库，保留测试卷。
- `scripts/accept_go_model.py --mode model` 创建额度不足、日志注入及提取失败合成任务，要求真实模型完成、证据引用合法、分类及恢复状态不被改变、通知送达；记录各任务从创建请求开始到发现事件的耗时。
- `--mode soak` 默认 12 轮，每轮 30 秒，持续创建 1 个异常及 2 个正常/取消任务；检查事件不重复、正常任务不误报、诊断及通知完成，并采样 CPU、内存、进程数、重启次数和队列状态。
- 持续运行只是 6 分钟实验规模验证，不代表生产压测或数日稳定性；发现时延只对本次依赖正常、实验负载下的样本负责。

实际结果以 `artifacts/go-tests.json`、`go-model-acceptance.json`、`go-soak-acceptance.json`、`go-smoke.json`、`go-browser.json` 为准。只有 `passed=true` 或检查全部通过的当前记录才算完成。

## 完成结果（2026-09-29）

Go 测试 79 项通过（含子测试，25 个测试组，0 跳过，竞态检测通过），完整业务回归 28 项通过，浏览器 11 项通过。持续投放 364.339 秒、36 个合成任务，异常发现耗时 1.099–15.148 秒，无重复事件、正常/取消任务无误报，诊断与通知完成且队列清空。12 次模型分析中 9 次成功、3 次超时后规则回退；真实中转站仍有响应波动，不能承诺每次 AI 请求成功。完整成功及失败边界见 go-validation.md；批量模型专项曾失败，保留失败记录，不把后续单场景成功改写成该批次通过。
